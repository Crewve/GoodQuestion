## **2. 지원 디바이스 & 화면 기준**

#### 실제 서비스는 다양한 디바이스·브라우저 환경(태블릿 기종, PC 브라우저, 모바일 가로 등)에 유연하게 대응되는 것을 목표로 함.(상대 단위 적용)

- **디자인 시안 기준: 태블릿 가로모드 1194×834px *(고정 해상도가 아닌 시안 기준값)***

| 우선순위 | 디바이스 | 디자인 기준 | 비고 |
| --- | --- | --- | --- |
| 1순위 | 태블릿 가로 모드 | 태블릿 기준 | 디바이스 뷰포트 기준 |
| 2순위 | PC 브라우저 | 콘텐츠 영역 기준 + 화면 확장 | 콘텐츠 영역 max-width 제한, 좌우 여백 영역 확장 (가운데 정렬) |
| 3순위 | 모바일 가로 | 태블릿 시안 대응 축소 | 모바일 세로모드는 지원 대상에서 우선 제외함 |

- 설계 우선순위: 태블릿 → PC → 모바일. (태블릿 기준을 최우선으로 지키는 방향으로 판단)**.**

### 2.1 화면 영역 고정 원칙 (Header & GNB)

- **Header / GNB 고정:** 스크롤이 허용되는 화면(보호자 화면 등)의 경우 화면 스크롤 또는 콘텐츠 변동 여부와 관계없이 Header 및 GNB 영역은 상하단 고정(Fixed/Sticky)되어 상시 노출.

### 2.2 레이아웃 및 스크롤 원칙

- **아이 대상 화면 (도입 / 전개 / 대화 / 미션 / 후속활동 등)**
  - **스크롤 미허용:** 화면 내 스크롤 없이 한 화면에 전체 요소를 담는 것을 기본 원칙으로 설계.
  - **PC 확장:** 전체 너비는 브라우저 기준 가변, 콘텐츠 영역은 `max-width`로 제한하여 레이아웃 과도 확장 방지.
  - **모바일 가로:** 아동용 최소 폰트/아이콘 크기 유지로 인해 공간 부족 발생 시, 예외적으로 세로 스크롤 허용 가능성 검토.
- **보호자 화면 (아이 대상 화면 외 전체)**
  - **스크롤 허용:** 세로 스크롤 허용.

### **2.3 화면 유형별 콘텐츠 최대폭**

- 화면 유형별 콘텐츠 최대폭은 Figma 시안에 고정값으로 반영

## 4. 터치 타깃 최소 크기

- **최소 터치 영역:** 아이 대상 화면의 경우 반응형 대응(모바일 ) 에 따라 요소 축소가 필요한 경우에도, 주요 조작 버튼을 포함한 모든 터치 타깃은 **최소 48×48px 이상**을 유지(표준이 아닌 최소한의 하한선 원칙을 기준으로 함)
- **의도:** 타깃 사용자(아동)의 미세한 조작 능력을 고려한 신뢰성 확보.

## 5. 색상 사용 원칙

- **시각 다중 보완:** 아이 대상 화면은 색상만으로 상태·의미를 구분하지 않고, \[색상 + 아이콘 + 텍스트\]를 반드시 함께 조합하여 전달
- 텍스트-배경 색상 대비: 일반 텍스트 4.5:1 이상, 큰 텍스트(18px Bold 이상 또는 24px 이상) 3:1 이상.

## **6. 인터랙션 원칙**

### **6.1 카드 순서 배열 인터랙션**

- 카드/요소 순서 배열: 드래그앤드롭이 기본 방식. 다만 저학년 아동은 손가락으로 정확히 잡고 옮기는 동작이 서툴 수 있어, 드래그가 어려운 경우 Tap-to-Move (탭투무브)로도 배열 가능하게 함께 제공 고려.
