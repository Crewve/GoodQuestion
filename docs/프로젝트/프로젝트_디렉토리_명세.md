# 굿퀘스천 프로젝트 디렉토리 명세

프로젝트: **굿퀘스천** — 아이가 동화 캐릭터와 음성으로 대화하며 생각하는 힘을 기르는 아동 학습 서비스 (해커톤 MVP)
작성일: 2026-08-07 · 기준: 초기 골격 커밋 시점

## 1. 기술 스택 요약

| 구분 | 선택 | 비고 |

## 3. 확장 예정 구조 (다음 단계 계획)

분석 문서(stt/llm/tts_analysis, 대화 작동 규칙)에서 확정된 아키텍처를 디렉토리로 배치한 계획이다. **아직 생성되지 않았으며**, 구현 착수 시 이 배치를 기준으로 한다.

```
GoodQuestion/
├── src/
│   ├── app/
│   │   ├── api/
│   │   │   ├── stt/route.ts       # POST: 오디오+힌트 → Whisper → 실패 게이트 → 교정 → 텍스트 반환
│   │   │   └── turn/route.ts      # POST: 확정 텍스트 → 저장 → 분석 → 규칙 → 생성/고정대사 → TTS → 응답
│   │   ├── story/[storyId]/       # 이야기 시작·장면 진행 화면
│   │   └── session/[sessionId]/   # 대화 화면 (턴 UI)
│   ├── lib/
│   │   ├── openai.ts              # OpenAI 단일 클라이언트 (키 1개·클라이언트 1개 원칙)
│   │   ├── supabase.ts            # 서버 전용 supabase-js 클라이언트 (service role)
│   │   ├── config.ts              # ANALYSIS_MODEL 등 역할별 모델 설정값 로더
│   │   ├── stt/                   # 힌트 구성·verbose_json 게이트·경량 교정 (stt_analysis §3)
│   │   ├── llm/                   # 분석·생성 호출부 + Zod 스키마 4필드 (llm_analysis §5)
│   │   ├── rules/                 # 진행 판단 규칙 엔진 — 순수 함수, 단위 테스트 대상
│   │   │   └── *.test.ts          # Vitest (누적·모드·종료 판정)
│   │   └── tts/                   # provider 어댑터(타입캐스트) + hash(voice+text) 캐시 (tts_analysis §3)
│   ├── components/                # 대화 UI·진행 상태 표시·녹음 버튼 등
│   ├── store/                     # Zustand 턴 상태머신 (녹음중/변환중/응답대기 등)
│   └── hooks/                     # useRecorder(MediaRecorder+RMS 사전 게이트), useAudioUnlock 등
├── scripts/
│   └── generate-fixed-audio.ts    # 고정 대사(character_opening/closing) 배치 TTS 생성 → Storage 업로드
├── supabase/
│   ├── schema.sql                 # stories·story_scenes·story_sessions·messages·utterance_analyses
│   └── seed.sql                   # 대표 이야기 1편 장면·고정 대사 시드
└── .env.example                   # 아래 환경변수 목록의 템플릿
```

### 환경변수 (예정)

| 변수 | 용도 |
|---|---|
| `OPENAI_API_KEY` | Whisper STT + LLM 공용 (서버 전용) |
| `TYPECAST_API_KEY` | TTS — 백엔드 프록시 경유, 브라우저 비노출 |
| `NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | DB·Storage 접근 (service role은 서버 전용) |
| `ANALYSIS_MODEL` / `GENERATION_MODEL` / `STT_CORRECTION_MODEL` | 역할별 모델 설정 — 기본 `gpt-4o-mini`, 품질 미달 시 생성만 상위 모델로 전환 |

### Supabase Storage 버킷 (예정)

| 버킷 | 내용 |
|---|---|
| `fixed-audio` | 고정 대사 사전 생성 mp3 (`{scene}_{character}.mp3`) — 공개 읽기 |
| `tts-cache` | 가변 질문 런타임 캐시 (`hash(voice_id+text).mp3`) — 공개 읽기 |

## 4. 컨벤션

- **임포트**: `src/` 하위는 `@/` 별칭 사용 (예: `@/lib/rules`)
- **네이밍**: API·코드는 camelCase, DB 컬럼은 snake_case — 경계에서 매핑 (연동기준_충돌검토 §1-6)
- **판단은 코드**: 대화 진행 판정 로직은 `src/lib/rules/`의 순수 함수에만 둔다. LLM 호출부에 판단 로직을 넣지 않는다
- **API 키**: 모든 외부 API 호출은 Route Handler(서버)에서만. 클라이언트 번들에 키가 들어가지 않게 한다
- **문서**: 기획·분석 산출물은 `docs/` 하위 분류 디렉토리(기획·모델선정·설계검토·프로젝트)에 한글 파일명으로 유지. 요구사항의 SoT는 Notion 문서이며(연동기준_충돌검토 §2-A), 저장소 문서는 분석·구현 기준 산출물
