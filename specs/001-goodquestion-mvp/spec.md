## User Scenarios & Testing *(mandatory)*

### User Story 1 - 이야기 진행: 음성 대화 턴 사이클 (Priority: P1)

아이가 「방귀 뀌는 며느리」 이야기를 진행한다. 도입·전개 장면에서는 내레이션이 한 문장씩 자동 재생되고, 대화 장면에서는 캐릭터(며느리·시아버지·마을 이장)가 음성으로 말을 걸면 아이가 음성으로 답한다. 시스템은 아이 발화를 텍스트로 변환해 8가지 사고 요소를 분석하고, 부족한 요소를 유도하는 캐릭터 응답을 생성해 음성으로 재생한다. 목표 요소가 모두 충족되거나 최대 턴에 도달하면 고정 클로징 대사를 재생하고 다음 장면으로 넘어간다.

**Why this priority**: 서비스의 핵심 가치("캐릭터와 음성으로 대화하며 생각하는 힘을 기른다")가 이 루프에 있다. 이것 없이는 데모가 성립하지 않는다.

**Independent Test**: UI 없이도 CLI(`stt-check`, `tts-check`, `simulate`)로 STT→분석→규칙→생성→TTS 왕복을 검증할 수 있고, UI가 붙으면 대화 화면 1개 장면으로 E2E 확인 가능.

**Acceptance Scenarios**:

1. **Given** 대화1 장면 진입, **When** 캐릭터 오프닝 재생이 끝나면, **Then** 마이크가 자동 활성화되고 상태 배지가 "생각을 말해보세요!"로 전환된다.
2. **Given** 아이가 발화를 마치고 보내기를 누르면, **When** 분석이 완료되면, **Then** 누적 요소가 갱신되고 부족 요소를 유도하는 캐릭터 응답(또는 클로징)이 음성으로 재생된다.
3. **Given** required_elements가 모두 충족되었거나 max_turns에 도달, **When** 종료 판정이 내려지면, **Then** LLM 호출 없이 사전 생성된 `character_closing` 오디오가 재생되고 다음 장면으로 이동한다.
4. **Given** STT가 실패 게이트(무음·환각·저신뢰)에 걸리면, **Then** 메시지를 생성하지 않고(턴 카운트 제외) 재시도 안내를 재생한다.

### User Story 2 - 미션 노출과 수행 (Priority: P2)

대화3(미션1: 방귀로 배 떨어뜨리기)·대화4(미션2: 단점을 장점으로 바꾸기)에서, 아이의 발화 흐름을 확인한 뒤 노출 조건이 충족되는 시점에 미션이 대화 화면 위 오버레이 팝업으로 노출된다. 아이는 음성으로 미션에 응답하고, 결과는 다음 캐릭터 반응에 반영된다.

**Why this priority**: 사고 확장의 핵심 장치이지만 US1 루프가 먼저 있어야 동작한다.

**Independent Test**: `simulate` CLI에 미션 노출 조건 시나리오 대본을 넣어 노출 판정·미션 응답 반영을 텍스트로 검증.

**Acceptance Scenarios**:

1. **Given** 대화3에서 아이가 해결 방향은 말했지만 방법이 구체적이지 않음, **When** 노출 조건 판정이 참이면, **Then** 화면 전환 없이 오버레이로 미션1이 노출된다.
2. **Given** 미션 응답 제출, **When** 분석 완료, **Then** 팝업 내용이 [미션 성공 완료]로 전환되고 "이야기 계속하기"로 대화 화면에 복귀한다.

### User Story 3 - 진입 여정: 로그인 → 아이 프로필 → 홈 → 이야기 선택 (Priority: P2)

보호자가 계정을 만들고(이메일, 약관 동의) 아이 프로필(캐릭터·이름·생년월일, 최대 3명)을 등록한다. 아이 프로필을 선택해 홈으로 진입하면 이어하기/추천 이야기가 보이고, 이야기 목록(주제·난이도 필터)과 상세를 거쳐 이야기를 시작한다.

**Why this priority**: 데모 시나리오의 시작점. 대화 루프보다 구현 위험이 낮은 표준 CRUD/화면 흐름.

**Independent Test**: 회원가입→프로필 등록→홈 진입→이야기 상세→시작하기까지 클릭 경로 E2E.

**Acceptance Scenarios**:

1. **Given** 신규 보호자, **When** 계정 생성과 아이 등록(1~3명)을 완료하면, **Then** 아이 프로필 선택 화면에 등록된 카드가 보인다.
2. **Given** 진행 중 세션 존재, **When** 홈 진입, **Then** 이어하기 카드(진행률 n/N·%)가 노출되고 "이야기 계속하기"가 마지막 지점 장면으로 이동한다.
3. **Given** 진행 중 세션 없음, **Then** 이어하기 미노출, 추천 6개 중 첫 카드는 '방귀 뀌는 며느리' 고정·클릭 가능, 나머지 5개는 클릭 불가.

---

### User Story 4 - 학습 완료 후속 활동 (Priority: P3)

대화 구간이 끝나면 장면 카드 4장을 이야기 순서대로 배열하고(서버 정답 판정, 재시도 가능), 정답 시 핵심 단어와 함께 전체 이야기를 음성으로 재구성해 말한다. 완료 시 학습 완료 화면(배지·요약)이 보이고 세션이 완료 처리된다.

**Why this priority**: 학습 마무리 장치. 핵심 대화 루프와 독립적으로 뒤에 붙는 화면들이며, `post_activity_config` 콘텐츠가 미정의라 기획 확정 의존.

**Independent Test**: 카드 배열 제출→판정→재구성 발화 저장→완료 화면까지 화면 흐름 단독 확인.

**Acceptance Scenarios**:

1. **Given** 카드 4장 슬롯 배치 완료, **When** 서버 판정이 오답이면, **Then** 배치 유지 상태로 재배치·재제출이 가능하고 attempt_count가 누적된다.
2. **Given** 재구성 발화 보내기, **Then** retelling_text·completed_at 저장 후 학습 완료 화면으로 이동하고 해당 이야기는 이어하기 대상에서 제외된다.

---

### User Story 5 - 마이페이지·시스템 메뉴 (Priority: P3)

보호자가 내정보(로그인 방식, 아이 프로필 목록, 주간 활동 요약)와 프로필 관리, 공지사항·고객센터·이용안내·로그아웃, 배지 화면(정적 UI)을 사용한다.

**Why this priority**: 데모 완성도용 보조 화면. 대부분 정적/단순 조회.

**Independent Test**: 각 메뉴 진입·표시·이동 경로 확인.

**Acceptance Scenarios**:

1. **Given** 내정보 화면, **When** 로그아웃 클릭, **Then** 확인 팝업 후 로그인 화면으로 이동한다.

### Edge Cases

- STT 결과가 무음·1~2자·환각(자막체 상투구, n-gram 반복)일 때 → 실패 게이트로 차단, 메시지 미생성·턴 카운트 제외, 재시도 안내.
- 마이크 권한 거부 → 안내 문구 후 권한 재요청 유도.
- LLM/TTS 장애 → 고정 대사 폴백, 캐릭터 응답 생성 실패 시 1회 자동 재시도, max_turns 직전 지연 시 타임아웃.
- TTS 재생 실패(내레이션) → 텍스트만 노출하고 "다시 듣기"로 재시도.
- 최대 턴 도달·목표 미충족 → 평가·지적 없이 짧은 반응 후 클로징으로 자연 연결.
- 'ㅇㅇ' 자리표시자 대사(대화1·대화4 오프닝) → 사전 생성 불가 문제 처리(치환 또는 런타임 TTS).
- 이야기 진행 중 "X 나가기" → 저장 규칙에 따라 재진입 지점 결정(도입은 항상 처음부터, 전개/대화는 scene_goal_met 기준).
- 아이 3명 등록 상태에서 추가 시도 → 카드 미노출/버튼 비활성으로 사전 차단.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 보호자는 이메일/비밀번호로 계정을 생성·로그인할 수 있어야 한다. 소셜 로그인은 카카오/구글/네이버 중 최소 1개 연동을 제공한다. [NEEDS CLARIFICATION: 휴대폰 SMS 본인인증(기능명세서 1.2.1)의 MVP 범위 — research.md에서 잠정 결정]
- **FR-002**: 보호자 계정당 아이 프로필을 1~3명 등록·관리(추가/수정)할 수 있어야 하며, 캐릭터(4종)·이름·생년월일(YYYYMMDD, 미래 불가)·아동 개인정보 동의(화면당 1회)를 받는다.
- **FR-003**: 홈은 이어하기(진행 중 세션 존재 시)와 추천 이야기 6개(3×2, 없으면 '방귀 뀌는 며느리' 첫 고정·유일 클릭 가능)를 노출한다. 진행률 n/N·%는 [공용] 장면 진행률 계산 규칙을 따른다(도입 포함 5분할: N=도입 1구간+전개·대화 쌍 수, 도입=1, 전개k·대화k=k+1 — 2026-08-14 정정, 종전 "도입 제외 쌍=1" 해석 폐기).
- **FR-004**: 이야기 목록은 주제(전체/다름/용기/친절/나눔)·난이도(전체/새싹/튼튼/도전) 단일 선택 AND 필터를 제공한다.
- **FR-005**: 이야기 진행은 도입(1) → 전개N → 대화N(미션 포함) → 학습완료(카드 배열→재구성) 순차 진행형이며 건너뛰기 불가. 진행률 바·텍스트, X 나가기(상세로 복귀)를 공통 제공한다.
- **FR-006**: 도입·전개는 `scene_description`(온점 분리) 문장 단위 자동 TTS 재생 + 이전/다음 화살표·다시 듣기, 마지막 문장에서 진행하기 버튼을 노출한다.
- **FR-007**: 대화 장면은 상태 배지 3종(캐릭터의 말을 듣고 있어요!/생각을 말해보세요!/말을 글자로 바꾸는 중이에요!)과 턴 사이클을 구현한다: 캐릭터 대사 자동 재생 → 재생 종료 시 마이크 자동 활성·녹음 자동 시작 → 아이가 마이크 버튼으로 종료 → STT 표시(수정 불가) → 보내기 클릭 시에만 저장·분석 요청.
- **FR-008**: STT는 Whisper API(`whisper-1`, verbose_json, 장면별 prompt 힌팅)로 변환하고, 실패 게이트(①1~2자 ②no_speech_prob>0.6 ③avg_logprob<-1.0 ④n-gram 반복 ⑤자막체 상투구 — 임계값은 설정으로 튜닝 가능)를 거쳐 경량 LLM(gpt-4o-mini)으로 맞춤법·띄어쓰기만 교정한다. `stt_raw_text`/`text`를 분리 유지하고, 게이트 실패 시 메시지를 생성하지 않는다(턴 카운트 제외). 원본 음성은 변환 후 즉시 폐기하며 어떤 저장소에도 남기지 않는다.
- **FR-009**: 발화 분석 LLM은 4필드 구조화 출력(`child_intent`/`main_point`/`detected_elements[{type, evidence}]`/`utterance_validity`)을 반환한다. 탐지는 항상 8요소 전체를 대상으로 하며 `elementCriteria`/`targetElements`는 인정 기준·참고 입력일 뿐 탐지 범위를 제한하지 않는다. evidence는 아이 발화 원문 인용이어야 하고 서버 후처리(인용 검증·중복 정리·약한 탐지 보정)를 거치며, LLM 원본(raw)과 확정본을 병행 저장한다.
- **FR-010**: 진행 판단은 LLM이 아닌 순수 코드 규칙 엔진이 수행한다: 누적 요소(accumulated)/부족 요소(missing) 계산, `turns_without_new_element`·`consecutive_low_information_turns` 카운트, NORMAL/GUIDED/CLOSING 판정, 종료 이유(GOAL_MET/MAX_TURNS) 확정. 규칙 엔진은 문장을 만들지 않는다.
- **FR-011**: 캐릭터 응답 LLM은 캐릭터 페르소나(fixtures/characters)를 반영하고, GUIDED 시 서버가 지정한 부족 요소 1~2개만 유도한다. 아동 안전 가드레일과 후검증(길이·금칙어)을 적용한다.
- **FR-012**: CLOSING 시 캐릭터 LLM을 호출하지 않고 사전 생성된 `story_scenes.character_closing` 오디오를 재생한다(2026-08-07 확정). 최대 턴 도달·목표 미충족 종료 시에도 짧은 반응 후 동일하게 클로징을 재생한다.
- **FR-013**: TTS는 타입캐스트 어댑터(`synthesize(text, voiceId)`)로 생성하되 백엔드 프록시 경유(키 비노출), 동시 호출 2 제한, `hash(voiceId+text)` 2층 캐시(로컬 디렉토리 + Storage `tts-cache`)를 적용한다. 고정 대사 14건(오프닝4·클로징4·내레이션5·시스템1)은 사전 생성해 Storage `fixed-audio`에 업로드한다. 시연물에 타입캐스트 출처 표기를 포함한다.
- **FR-014**: 캐릭터(며느리·시아버지·마을 이장·내레이터) → voice_id 매핑을 확정하고 데이터(JSON/DB)로 관리한다.
- **FR-015**: 미션1(대화3)·미션2(대화4)는 노출 조건 충족 시 오버레이 팝업으로 노출된다(URL·화면 전환 없음). 미션 중 마이크는 자동 시작이 아닌 버튼 시작이며, 응답 제출 후 같은 팝업에서 [미션 성공 완료]로 전환된다. 미션 데이터는 장면과 별도 구조로 관리한다.
- **FR-016**: 학습완료 1단계 카드 배열은 서버가 `post_activity_config` 기준으로 정답 판정하며(프런트 판정 금지), `is_order_correct`·`attempt_count`를 upsert 저장한다. 2단계 재구성 발화는 `retelling_text`·`completed_at`을 저장한다. 재진입 라우팅은 저장 값 기준.
- **FR-017**: 세션 재개: `story_sessions`의 `current_scene_id`+`scene_goal_met`으로 진행 지점을 계산해 이어하기한다. 도입 중단은 저장하지 않고 항상 처음부터.
- **FR-018**: 콘텐츠(장면·대사·캐릭터·미션)는 코드에 하드코딩하지 않고 `fixtures/` → DB 시드 경유로 주입한다.

### Key Entities *(include if feature involves data)*

- **보호자 계정(User)**: 이메일 인증 주체. 아이 프로필 1~3 보유.
- **아이 프로필(Child)**: 캐릭터 아바타·이름·생년월일. 세션의 주체. 아동 개인정보 동의(child_consents) 연계.

- **장면(StoryScene)**: `scene_order`·`scene_type`(도입/전개/대화)·내레이션 또는 `character_opening/closing`·`scene_goal`·`required_elements`·`preferred_turns`·`max_turns`. `scene_type` 컬럼 추가 필요(기능명세서 비고).
- **캐릭터(Character)**: 페르소나 traits, 등장 장면, voice_id 매핑.
- **미션(Mission)**: 장면 연계(대화3→미션1, 대화4→미션2)·노출 조건·목적·완료 콘텐츠. 별도 테이블 필요(기능명세서 비고).
- **학습 세션(StorySession)**: 아이×이야기 진행 상태 — `current_scene_id`·`scene_goal_met`·후속활동 결과(`is_order_correct`·`attempt_count`·`retelling_text`·`completed_at`).
- **메시지(Message)**: 턴별 발화 — 아이(`stt_raw_text`/`text`)와 캐릭터 발화 누적.
- **발화 분석(UtteranceAnalysis)**: 4필드 분석 결과 — LLM 원본(raw)과 후처리 확정본 병행.
