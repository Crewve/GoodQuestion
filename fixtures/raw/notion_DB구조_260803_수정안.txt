  ▸ 테이블/컬럼 정의서
    ## 1. parents — 보호자 계정
    보호자 로그인 계정과 기본 정보를 저장한다.
    [TABLE]
      | 컬럼명 | 설명 | 예시 | 권장 타입 | 필수 |
      | id | 보호자 고유번호. Supabase Auth 사용자 ID와 동일하게 사용 | a12f... | uuid | Y |
      | name | 보호자 이름 또는 닉네임 | 이혜민 | varchar | Y |
      | created_at | 계정 생성 일시 | 2026-07-23 13:00 | timestamptz | Y |
    ### 참고
    - 이메일, 비밀번호, 로그인 인증은 Supabase Auth에서 관리한다.
    - 별도의 auth_user_id는 만들지 않는다.
    - parents.id와 Supabase의 auth.users.id를 동일하게 사용한다.
    ---
    ## 2. children — 아이 정보
    보호자가 등록한 아이의 기본 프로필을 저장한다.
    [TABLE]
      | 권장 타입 | 예시 | 필수 | 컬럼명 | 설명 |
      | uuid | c56e... | Y | id | 아이 고유번호 |
      | uuid | a12f... | Y | parent_id | 아이를 등록한 보호자의 ID |
      | varchar | 민준 | Y | name | 아이 이름 또는 닉네임 |
      | smallint | 2018 | Y | birth_year | 아이의 출생연도 |
      | timestamptz | 2026-07-23 13:10 | Y | created_at | 아이 프로필 등록 일시 |
    ### 참고
    - 한 명의 보호자가 여러 아이를 등록할 수 있다.
    - 서비스에서는 현재 연도와 birth_year를 이용해 연령을 계산한다.
    - 출생연도만 저장하므로 정확한 생일 기준 만 나이가 아니라 연도 기준 연령이 된다.
    - 아이 프로필 진입용 PIN은 현재 MVP에서 제외한다.
    ---
    ## 3. child_consents — 아동 개인정보 처리 동의
    아동 데이터 처리에 대한 보호자의 동의 기록을 저장한다.
    [TABLE]
      | 예시 | 필수 | 권장 타입 | 설명 | 컬럼명 |
      | co01... | Y | uuid | 동의 기록 고유번호 | id |
      | c56e... | Y | uuid | 동의 대상 아이 ID | child_id |
      | mvp_v1 | Y | varchar | 동의한 개인정보 처리 안내문 버전 | consent_version |
      | institution_paper | Y | varchar | 보호자 확인 방식 | verification_method |
      | 2026-07-23 13:05 | Y | timestamptz | 동의 일시 | consented_at |
      | null | 선택 | timestamptz | 동의 철회 일시 | withdrawn_at |
    ### verification_method 예시
    - authenticated_parent: 로그인한 보호자가 온라인에서 동의
    - institution_paper: 기관을 통해 종이 동의서 확인
    - mobile_verification: 휴대전화 본인 확인
    ### 참고
    - 동의가 없거나 철회된 아이는 새로운 이야기 세션을 시작할 수 없다.
    - MVP에서는 서비스 이용에 필요한 아동 데이터 처리 동의 한 종류만 관리한다.
    - 원본 음성을 저장하지 않으므로 음성 파일 저장 동의는 별도로 만들지 않는다.

    ## 4. stories — 이야기
    서비스에서 제공하는 이야기의 기본 정보와 말하기 후 활동 설정을 저장한다.
    [TABLE]
      | 권장 타입 | 필수 | 컬럼명 | 설명 | 예시 |
      | uuid | Y | id | 이야기 고유번호 | s01... |
      | varchar | Y | title | 이야기 제목 | 토끼전 |
      | text | Y | summary | 이야기 목록·상세 화면에 표시할 소개 | 용왕을 살리기 위해 자라가 토끼를 찾아가는 이야기 |
      | varchar | Y | difficulty | 이야기 난이도 | basic |
      | text[] | 선택 | topics | 이야기의 주요 주제 | ["정직", "관점", "해결"] |
      | smallint | 선택 | estimated_minutes | 예상 활동 시간 | 15 |
      | jsonb | 선택 | post_activity_config | 카드 내용, 정답 순서, 이야기 재구성 핵심 단어 | 아래 예시 참고 |
      | varchar | Y | status | 이야기 공개 및 운영 상태 | published |
    ### post_activity_config 예시
    ```
{
  "cards": [
    {
      "id":"card_1",
      "text":"용왕이 병에 걸렸어요.",
      "correct_order":1
    },
    {
      "id":"card_2",
      "text":"자라가 토끼를 찾아갔어요.",
      "correct_order":2
    }
  ],
  "retelling_keywords": ["용왕","자라","토끼","용궁"
  ]
}
    ```
    ### status 예시
    - draft: 제작 중
    - published: 서비스에 공개
    - archived: 신규 이용 중지
    ### 참고
    - 카드 내용과 정답 순서는 별도 카드 테이블을 만들지 않고 post_activity_config에 저장한다.
    - 별도의 story_versions 테이블은 MVP에서 만들지 않는다.
    - 이미 세션에서 사용된 이야기를 수정해야 한다면 기존 내용을 직접 변경하지 않고, 이야기와 장면을 복사해 새로운 story_id로 등록한다.

    ## 5. story_scenes — 장면
    이야기를 구성하는 장면과 장면별 대화 기준을 저장한다.
    [TABLE]
      | 설명 | 예시 | 컬럼명 | 필수 | 권장 타입 |
      | 장면 고유번호 | sc01... | id | Y | uuid |
      | 장면이 포함된 이야기 ID | s01... | story_id | Y | uuid |
      | 이야기 안에서 장면이 진행되는 순서 | 2 | scene_order | Y | smallint |
      | 장면 상황과 대화 맥락 | 자라는 토끼를 속여 용궁으로 데려갈지 고민한다. | scene_description | Y | text |
      | 장면의 갈등·고민 요약 | 사실을 말하면 토끼가 따라오지 않을 것 같아 고민한다. | conflict | Y | text |
      | 현재 장면에서 아이와 대화하는 캐릭터 | 며느리 | character_name | Y | varchar |
      | 장면 시작 시 캐릭터가 말하는 고정 첫 대사 | 아이고… 배가 이렇게 빵빵한데도 참아야 하니 큰일이야. | character_opening | Y | text |
      | 장면 종료 시 캐릭터가 말하는 고정 마지막 대사 | 그래도 아직은 못 말하겠어. 조금만 더 참아 볼게. | character_closing | Y | text |
      | 장면에서 이끌어내고자 하는 발화 목표 | 며느리의 마음을 이해하면서 방법을 함께 이야기한다. | scene_goal | Y | text |
      | 장면 목표 충족에 필요한 사고 요소 | ["EMPATHY", "REASON", "SOLUTION"] | required_elements | Y | text[] |
      | 목표 충족으로 종료하기 위한 최소 아이 발화 횟수 | 3 | preferred_turns | Y | smallint |
      | 장면에서 허용하는 최대 아이 발화 횟수 | 6 | max_turns | Y | smallint |
    ### 참고
    ### required_elements 허용 값
    - DECISION, REASON, PERSPECTIVE, SOLUTION, RESULT, EMOTION, EMPATHY, REQUEST
    - 장면마다 위 집합의 부분 집합(1~8개)을 둔다.
    - id는 장면 자체의 고유번호다.
    - story_id는 이 장면이 어느 이야기에 포함되는지를 나타낸다.
    - 고정 마지막 대사(character_closing)는 두지 않는다. 종료 시 서버가 CLOSING 모드를 정하고 캐릭터 LLM이 마무리 대사를 생성한다.
    - required_elements는 아이가 한 번의 발화에서 모두 말해야 한다는 뜻이 아니다. 현재 장면의 여러 발화를 통해 목표 요소를 누적해서 확인한다.
    ### 장면 진행 순서
    ```
character_opening
→ 아이와 캐릭터 대화
→ 목표 충족 또는 최대 발화 횟수 도달
→ CLOSING 모드로 캐릭터 LLM이 마무리 대사 생성
→ 다음 장면 이동
    ```

    ## 6. story_sessions — 이야기 진행 기록
    아이가 특정 이야기를 한 번 시작하고 진행한 전체 기록과 현재 장면의 상태를 저장한다.
    [TABLE]
      | 컬럼명 | 필수 | 설명 | 예시 | 권장 타입 |
      | id | Y | 이야기 세션 고유번호 | ss01... | uuid |
      | child_id | Y | 이야기를 진행한 아이 ID | c56e... | uuid |
      | story_id | Y | 진행한 이야기 ID | s01... | uuid |
      | current_scene_id | 선택 | 현재 진행 중인 장면 ID | sc02... | uuid |
      | current_child_turn_count | Y | 현재 장면에서 아이가 말한 횟수 | 2 | smallint |
      | accumulated_elements | Y | 현재 장면에서 누적 확인된 사고 요소 | ["REASON", "PERSPECTIVE"] | text[] |
      | last_detected_elements | Y | 직전 아이 발화에서 새로 확인된 요소 | ["PERSPECTIVE"] | text[] |
      | last_response_mode | 선택 | 직전 확정 응답 모드 | GUIDED | varchar |
      | last_guidance_target | 선택 | GUIDED 또는 soft-cue 대상 사고 요소 | SOLUTION | varchar |
      | turns_without_new_element | Y | 신규 요소 없이 이어진 아이 발화 횟수 | 1 | smallint |
      | consecutive_low_information_turns | Y | 저정보 발화 연속 횟수 | 0 | smallint |
      | scene_goal_met | Y | 현재 장면 목표가 충족됐는지 | false | boolean |
      | scene_end_reason | 선택 | 현재 장면 종료 이유 | GOAL_MET | varchar |
      | status | Y | 이야기 진행 상태 | in_progress | varchar |
      | started_at | Y | 이야기 시작 일시 | 2026-07-23 13:30 | timestamptz |
      | completed_at | 선택 | 이야기와 후속 활동 완료 일시 | 2026-07-23 13:50 | timestamptz |
      | last_activity_at | Y | 마지막으로 활동한 일시 | 2026-07-23 13:40 | timestamptz |
    ### status 예시
    - in_progress: 이야기 대화 진행 중
    - post_activity: 말하기 후 활동 진행 중
    - completed: 이야기와 후속 활동 완료
    - stopped: 사용자가 중단
    ### last_response_mode 예시
    - NORMAL: 일반 반응
    - GUIDED: 부족한 요소로 유도
    - CLOSING: 장면 종료. 고정 마지막 대사(character_closing)를 재생한 뒤 다음 장면으로 이동
    ### scene_end_reason 예시
    - GOAL_MET: 최소 턴 이상 + 필수 요소 충족
    - MAX_TURNS: 최대 아이 발화 횟수 도달
    ### 참고
    - current_scene_id와 last_activity_at은 이어하기 기능에 사용한다.
    - turns_without_new_element: 새 사고 요소가 안 잡힌 턴이 2번 연속이면 유도
    - consecutive_low_information_turns: SHORT/UNCLEAR/OFF_TOPIC이 2번 연속이면 유도
    - 이전 장면에서 나온 발화와 분석 결과는 messages와 utterance_analyses에 남는다.

    ## 7. messages — 대화 기록
    하나의 이야기 세션에서 발생한 아이와 캐릭터의 모든 발화를 순서대로 저장한다.
    [TABLE]
      | 권장 타입 | 컬럼명 | 예시 | 설명 | 필수 |
      | uuid | id | m01... | 메시지 고유번호 | Y |
      | uuid | session_id | ss01... | 메시지가 포함된 이야기 세션 ID | Y |
      | uuid | scene_id | sc02... | 메시지가 발생한 장면 ID | Y |
      | varchar | speaker_type | child | 발화자 유형 | Y |
      | integer | turn_order | 5 | 세션 전체에서 메시지가 발생한 순서 | Y |
      | text | text | 토끼가 모르고 따라가면 억울하니까 속이면 안 돼요. | 화면과 분석에 사용하는 확정 발화 텍스트 | Y |
      | text | stt_raw_text | 토끼가 모르고 따라가면 억울하니까 속이면 안되요 | STT가 최초로 변환한 텍스트 | 선택 |
      | timestamptz | created_at | 2026-07-23 13:34 | 메시지 생성 일시 | Y |
    ### speaker_type 예시
    - child: 아이 발화
    - character: 캐릭터 발화
    - system: 시스템 안내
    ### 참고
    - 캐릭터가 생성한 대사뿐 아니라 고정 첫 대사와 고정 마지막 대사도 messages에 저장한다.
    - stt_raw_text는 아이 발화에만 저장한다.
    - 원본 음성 파일은 저장하지 않는다.
    - STT 변환에 실패해 확정된 텍스트가 없는 경우 메시지를 생성하지 않는다.
    - 첫 대사와 마지막 대사는 story_scenes에서 불러온 뒤 실제 재생 시점에 messages에 저장한다.

    ## 8. utterance_analyses — 발화 분석
    아이 메시지 한 건에 대한 발화 분석 결과를 저장한다.
    [TABLE]
      | 설명 | 컬럼명 | 권장 타입 | 예시 | 필수 |
      | 분석 결과 고유번호 | id | uuid | ua01... | Y |
      | 분석 대상 아이 메시지 ID | message_id | uuid | m01... | Y |
      | 이번 발화의 중심 의도 | child_intent | varchar | REASONING | Y |
      | 아이 말의 핵심 뜻 | main_point | text | 속이면 토끼가 억울해져요. | 선택 |
      | 이번 발화에서 확인된 사고 요소와 근거 | detected_elements | jsonb | 아래 예시 | Y |
      | 이번 발화의 유효성 | utterance_validity | varchar | VALID | Y |
    ### detected_elements 예시
    ```
[
{ "type": "REASON", "evidence": "억울하니까" },
{ "type": "PERSPECTIVE", "evidence": "토끼가 모르고 따라가면" }
]
    ```
    이번 최신 아이 발화 한 건에서 확인된 요소만 저장한다.

현재 장면 전체의 누적 요소는 `story_sessions.accumulated_elements`에 type만 합쳐 저장한다.
    ```
{
"accumulated_elements": ["PERSPECTIVE", "REASON"]
}
    ```
    ### 부족한 요소
    missing_elements는 DB 컬럼으로 저장하지 않는다.
    서버에서 아래와 같이 계산한다.
    missing_elements
    = story_scenes.required_elements
    - story_sessions.accumulated_elements
    ### utterance_validity 기준
    - VALID: 의미가 파악되는 유효 발화
    - SHORT: 지나치게 짧음
    - UNCLEAR: 뜻을 알기 어려움
    - OFF_TOPIC: 장면과 관련 없음
    - PLAYFUL: 장난·소리 흉내 등
    ### child_intent 예시
    - QUESTION, OPINION, REASONING, SOLUTION, DECISION, PERSPECTIVE, EMOTION, REQUEST, CHALLENGE, PLAYFUL, OFF_TOPIC, SHORT_RESPONSE, UNCLEAR
    ### 참고
    - 아이 메시지만 분석한다.
    - 하나의 아이 메시지에는 분석 결과 한 건만 저장한다.
    - STT 실패는 확정된 아이 메시지가 아니므로 발화 분석 대상이 아니다.
    - 분석 LLM은 child_intent, main_point, detected_elements, utterance_validity만 제안한다.
    - 장면 목표 충족·응답 모드(NORMAL / GUIDED / CLOSING)·종료 이유는 story_sessions에서 서버 규칙으로 확정한다.
    - utterance_validity = VALID이어도 필수 요소가 남으면 scene_goal_met은 false일 수 있다.
    - CLOSING이 결정되면 LLM이 마지막 대사를 생성하지 않는다.
    - 서버가 story_scenes.character_closing을 조회해 messages에 저장하고 재생한다.
    ---
    ## 9. post_activity_results — 말하기 후 활동 결과
    이야기 종료 후 진행하는 순서 배열과 이야기 재구성 활동의 최종 결과를 저장한다.
    [TABLE]
      | 예시 | 권장 타입 | 필수 | 컬럼명 | 설명 |
      | pa01... | uuid | Y | id | 활동 결과 고유번호 |
      | ss01... | uuid | Y | session_id | 활동 대상 이야기 세션 ID |
      | ["card_2", "card_1", "card_3"] | text[] | 선택 | submitted_order | 아이가 최종 제출한 카드 순서 |
      | true | boolean | 선택 | is_order_correct | 카드 배열 정답 여부 |
      | 2 | smallint | Y | attempt_count | 순서 배열을 시도한 횟수 |
      | 자라는 토끼를 속이려고 했지만 다른 방법을 찾기로 했어요. | text | 선택 | retelling_text | 핵심 단어를 사용해 아이가 다시 말한 이야기 |
      | 2026-07-23 13:50 | timestamptz | 선택 | completed_at | 말하기 후 활동 완료 일시 |
    ### 참고
    - 세션당 최종 활동 결과 한 건만 저장한다.
    - 순서 배열의 시도별 과정은 저장하지 않는다.
    - 카드 내용과 정답 순서는 stories.post_activity_config에서 불러온다.
    - 정답 여부는 프런트엔드가 결정하지 않고 서버에서 계산한다.

    # 추후 확장 테이블
    아래 테이블은 현재 MVP 구현 필수 대상이 아니다.
    ## 10. reports — 보호자 리포트
    아이의 대화와 발화 분석 결과를 종합해 보호자에게 보여줄 내용을 저장한다.
    [TABLE]
      | 설명 | 컬럼명 | 권장 타입 |
      | 리포트 고유번호 | id | uuid |
      | 리포트 대상 이야기 세션 ID | session_id | uuid |
      | 아이의 전체 활동 요약 | summary | text |
      | 아이가 잘 보여준 말하기 요소 | strengths | text 또는 jsonb |
      | 다음에 연습하면 좋은 말하기 요소 | next_focus | text 또는 jsonb |
      | 리포트 생성 일시 | created_at | timestamptz |
    ### 참고
    - 보호자 리포트를 실제 MVP 기능에 포함할 때 구현한다.
    - 대표 발화는 필요할 때 messages에서 조회하거나 리포트 내용에 포함한다.
    ---
    ## 11. analysis_versions — 분석 버전
    분석 모델과 프롬프트가 여러 버전으로 운영될 때 사용하는 관리 테이블이다.
    [TABLE]
      | 권장 타입 | 설명 | 컬럼명 |
      | uuid | 분석 버전 고유번호 | id |
      | varchar | 분석 버전명 | version_name |
      | varchar | 사용한 LLM 또는 분석 모델 | model_name |
      | text | 분석 프롬프트와 규칙 요약 | prompt_summary |
    ### 참고
    MVP에서는 별도 테이블 없이 utterance_analyses.analysis_version에 mvp_v1 같은 문자열만 저장해도 충분하다.
    ---
    ## 12. wordbook — 단어장
